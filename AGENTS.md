# AGENTS.md

Руководство для агентов, работающих в этом репозитории.

## Что это за проект

**Denchiku** — аудиоплеер для рабочего стола GNOME, сфокусированный на управлении
медиатекой. Язык — C (C11), GUI — GTK 4 + Libadwaita, воспроизведение и чтение
тегов — GStreamer (`gst-discoverer`/`playbin`), обложки — GdkPixbuf.

Весь код и комментарии — на русском. Новые комментарии писать на русском,
объясняя **почему**, а не «что» (см. существующие комментарии в заголовках).

## Сборка и запуск

Зависимости описаны в `README.md` (libadwaita-1, gstreamer-1.0,
gstreamer-pbutils-1.0, gdk-pixbuf-2.0, meson, ninja).

```bash
meson setup build          # первичная конфигурация (каталог build/ уже создан)
meson compile -C build     # сборка
./build/denchiku              # запуск
```

Эквивалент: `ninja -C build`. Установка: `meson install -C build`.

Особенности:
- Тестов нет, линтера нет, CI нет. Единственная проверка — успешная сборка
  (`meson compile -C build`). Всегда собирать после правок.
- Флаги сборки: `warning_level=2`, `c_std=c11` (`meson.build`). Правки должны
  собираться без новых предупреждений.
- В проекте нет `.gitignore`; `build/` не отслеживается git.

## Правила добавления кода

- **Новый .c-файл обязательно добавить в `sources` в `meson.build`**, иначе он не
  попадёт в сборку. Include-пути уже включают `src` и `src/ui`.
- Заголовки используют `#pragma once` (не `#ifndef`-гарды).
- Публичные функции — с префиксом модуля (`track_`, `player_`, `library_view_`,
  `ui_`, `media_browser_` и т.д.).
- GObject используется только для виджетов; собственные типы — обычные `struct`
  с `typedef struct _Foo Foo` в заголовке и определением `struct _Foo` в .c.
- Управление памятью ручное: `g_new0`/`g_free`, `g_ptr_array_*`, `g_strfreev`.
  Владение описывается в комментариях к заголовкам («владеет элементами»,
  «заимствованный»).
- Стиль: отступ 4 пробела, открывающая `{` на той же строке, короткие `static`
  функции-хелперы, выравнивание списков инициализации.

## Структура

```
src/        ядро: модель трека, кэш, сканер, слежение за файлами, плейлисты, плеер, состояние, настройки
src/ui/     интерфейс: окно, разделы медиатеки, плейлисты, плеер-бар, очередь, меню
  icons/    собственные символические иконки (в gresource)
meson.build описание сборки
```

Ядро (`src/`):
- `track.[ch]` — модель `Track` и разбиение тегов (`track_split_artists`,
  `track_split_genres`).
- `scanner.[ch]` — инкрементальное сканирование папки «Музыка» в фоновом потоке:
  теги перечитываются только у новых/изменённых файлов (сверка `mtime`+размер).
- `watcher.[ch]` — живое слежение за медиатекой: рекурсивные `GFileMonitor`
  (inotify), дебаунс событий, перечитывание тегов в пуле потоков, батч-доставка
  обновлений в UI. Мониторы каталогов и разбор идут вне главного потока.
- `cache.[ch]` — кэш медиатеки: единое in-memory-хранилище `GKeyFile`
  (группа `[track:<uri>]` на трек, ключи `mtime`/`size`), потокобезопасные
  инкрементальные правки и отложенная атомарная запись на диск.
- `playlist.[ch]` — плейлисты как m3u/m3u8 на диске, включая «Любимые треки».
- `player.[ch]` — обёртка над GStreamer: очередь, перемешивание/повтор, громкость.
- `state.[ch]` — состояние сессии (окно, очередь, вид браузера) в `~/.config`.
- `settings.[ch]` — настройки tag-splitting, глобальный синглтон.

Интерфейс (`src/ui/`):
- `window.c` — `WindowState` (владеется через `g_object_get_data(window,
  "window-state")`), верхний layout, действия, горячие клавиши, сессия.
- `library_view.c` — агрегирует 4 раздела: альбомы, исполнители, жанры, треки.
- `media_browser.[ch]` — переиспользуемый виджет сетка/список для модели.
- `view_controls.[ch]` — режим, зум, сортировка; enum'ы `ViewMode`/`ViewZoom`/
  `ViewSortField`.
- `track_menu.[ch]` — контекстное меню трека; поведение зависит от `TrackContext`
  (вкладка, страница альбома, очередь, плеер-бар...).
- `player_bar.c` — плеер-бар и полноэкранный плеер в `AdwBottomSheet`; адаптивность.
- `queue_view.c` — панель очереди с перетаскиванием (`GtkDropTarget` на `GtkListBox`).

## Хранилища данных

- `~/.cache/denchiku/library.cache` — список треков; `~/.cache/denchiku/covers/` — обложки.
- `~/.local/share/denchiku/playlists/` — плейлисты (в т.ч. `favorites.m3u8`).
- `~/<Музыка>` — папка сканирования (XDG).
- `~/.config/denchiku/state.ini` — состояние сессии; `settings.ini` — tag-splitting.

## Важные ограничения UI (учитывать при правках вёрстки)

- **Минимумы содержимого `AdwBottomSheet`**: `height-request` — это минимальная
  высота, большое значение раздувает минимум шторки и вызывает ошибку
  «AdwBottomSheet ... exceeds AdwApplicationWindow height/width». Минимум
  плеер-бара и содержимого шторки не должен превышать размер окна; для обнуления
  минимальной ширины есть `ui_create_min_width_bin()`/`ui_measure_min_width()`.
- **Единый брейкпоинт** `AdwBreakpoint` `max-width: 650sp` в `window.c`:
  сворачивает сайдбар, включает mobile у плеер-бара и открытие шторки. Порог в
  `sp` — сохранять синхронность при масштабировании.
- Минимальный размер окна задан `gtk_widget_set_size_request` = 360×400
  (оба размера указывать явно, `-1` сбрасывает штатный минимум).
- Через `AdwBottomSheet`/`AdwOverlaySplitView` нельзя задавать минимумы,
  превышающие окно: узкое окно обязано уходить в компактный режим.
- Снятие скриншотов в GNOME 51 внешними вызовами запрещено
  (org.gnome.Shell.Screenshot отвечает «Screenshot is not allowed») — для проверки
  вида использовать запуск приложения пользователем, а не скриншот-скрипты.
